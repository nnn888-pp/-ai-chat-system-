# AI 聊天对话系统 PRD

| 项目 | 内容 |
| --- | --- |
| 产品名称 | AI 聊天对话系统（ai-chat-system） |
| 文档版本 | v1.0 |
| 阶段 | V1（第一版）范围定义 |
| 前端框架 | Vue 3 + Vite |
| 目标用户 | 单个使用者（支持多账号注册，但无管理员体系） |

## 1. 背景与目标

在基础版聊天页面之上，构建一个**可接入多种模型**的本地化 AI 聊天系统：既能调用远端第三方大模型，也能加载自己训练的全量微调 / LoRA 微调模型（原生 `.pt` 格式，不转 GGUF）。同时补齐账户体系中的个人信息修改、密码修改能力，并对页面视觉做整体优化。

### 1.1 核心目标

1. 对话可用：新建、重命名、删除会话，会话内可切换模型。
2. 模型可扩展：远端模型 + 本地训练模型统一抽象，新增模型只需放文件 / 加配置。
3. 账户安全：密码哈希存储，不在数据库中保存明文。
4. 界面美观：视觉质量不低于基础版，布局与交互专业。

### 1.2 不在本期范围（明确排除）

- RAG / 知识库 / 文档问答
- 文件上传与解析（PDF、图片、语音）
- 团队协作、分享链接、多用户会话共享
- 管理员后台、用户封禁、额度计费
- 移动端专用适配（仅保证桌面浏览器正常）
- 模型在线训练 / 在系统内发起微调

## 2. 用户角色

| 角色 | 说明 | 主要权限 |
| --- | --- | --- |
| 游客 | 未登录用户 | 注册、登录 |
| 登录用户 | 系统唯一业务角色 | 全部会话、消息、模型、个人资料操作，数据仅可见自己的 |

## 3. 功能需求

### 3.1 账户模块（P0）

| 编号 | 功能 | 说明 | 验收要点 |
| --- | --- | --- | --- |
| A-01 | 用户注册 | 用户名 + 密码 + 昵称，用户名唯一 | 重复用户名返回明确提示；密码强度至少 6 位 |
| A-02 | 用户登录 | 用户名 + 密码，签发 JWT | 密码错误返回统一错误码，不暴露"用户不存在/密码错误"的区别 |
| A-03 | 个人信息查看与修改 | 修改昵称、头像（可先用文字头像 / 预设色块）、邮箱 | 修改后刷新页面仍生效 |
| A-04 | 密码修改 | 校验原密码 → 设置新密码 | 修改成功后其他已登录 token 可选失效；新密码不可与旧密码相同 |
| A-05 | 密码安全存储 | 数据库仅存 bcrypt 哈希 | 直接查库无法还原明文 |
| A-06 | 退出登录 | 清除本地 token，跳转登录页 | 退出后访问聊天页自动跳登录 |

### 3.2 会话管理模块（P0）

| 编号 | 功能 | 说明 | 验收要点 |
| --- | --- | --- | --- |
| C-01 | 会话列表 | 左侧列表按更新时间倒序，展示标题与最后一条消息摘要 | 刷新后顺序一致 |
| C-02 | 新建会话 | 创建后自动选中，标题默认为"新对话"或首条消息前 20 字 | 会话归属当前用户 |
| C-03 | 重命名会话 | 双击标题或菜单内重命名 | 标题长度限制 50 字，空标题不允许 |
| C-04 | 删除会话 | 二次确认后删除 | 删除后其消息一并不可见，列表立即更新 |
| C-05 | 会话内切换模型 | 输入框上方模型选择器，切换仅影响当前会话后续消息 | 历史消息保留原模型标识 |
| C-06 | 会话隔离 | 用户 A 无法通过接口访问用户 B 的会话 | 返回 403/404 |

### 3.3 消息模块（P0）

| 编号 | 功能 | 说明 | 验收要点 |
| --- | --- | --- | --- |
| M-01 | 发送消息 | 文本输入，Enter 发送 / Shift+Enter 换行 | 发送后立即上屏，占位"正在生成" |
| M-02 | 上下文携带 | 默认携带当前会话最近 N 轮历史（N 可配置，默认 10 轮） | 超长时按 token 或条数截断 |
| M-03 | 消息持久化 | 用户消息与 AI 回复均入库，含使用的模型标识 | 刷新后完整还原 |
| M-04 | 生成失败处理 | 超时、模型加载失败、远端 API 报错时给出可读提示 | 失败消息标记为 error 状态，可重试 |
| M-05 | 消息操作 | 复制回复内容；清空当前会话消息 | 清空需二次确认 |
| M-06 | 流式输出（P1） | 逐字返回，前端打字机效果 | 中断时可停止生成 |

### 3.4 模型管理模块（P0）

| 编号 | 功能 | 说明 | 验收要点 |
| --- | --- | --- | --- |
| D-01 | 模型列表 | 返回所有可用模型，标注类型（远端 / 本地）与能力 | 前端选择器可见 |
| D-02 | 远端模型接入 | 通过 OpenAI 兼容协议调用（Base URL + API Key） | 密钥不出现在前端响应中 |
| D-03 | 本地模型接入 | 加载本地训练产物（全量 `.pt` / LoRA adapter） | 系统启动或手动刷新后自动出现在列表 |
| D-04 | 自动识别加载 | 扫描 `models/` 目录，按目录内 `model_config.json` 识别类型与参数 | 新增目录无需改代码即可被识别 |
| D-05 | 本地模型状态 | 展示"未加载 / 加载中 / 就绪 / 失败" | 加载失败可在界面看到原因 |

### 3.5 界面与交互（P0）

- 登录 / 注册页：居中卡片，含品牌区与表单校验提示。
- 主界面：左侧会话栏 + 右侧聊天区，桌面端最小宽度 1280px 下不出现横向滚动。
- 消息气泡区分用户 / AI，AI 气泡支持 Markdown 渲染与代码高亮（P1）。
- 内置 3 套配色主题可切换（P1），默认主题为深色科技风或浅色简洁风，二选一在开发前定稿。
- 所有异步操作有 loading 态；空状态（无会话、无消息、无模型）有引导文案。

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 安全 | 密码 bcrypt 哈希；JWT 鉴权；接口按用户 ID 过滤数据；远端 API Key 仅存后端环境变量 |
| 性能 | 首次加载本地模型允许较慢，但需返回进度状态；单次生成响应首个 token 时间不做硬性指标；同一模型进程内只加载一份 |
| 稳定 | 本地模型推理异常不得导致后端进程退出 |
| 兼容 | Chrome / Edge 最新版；后端 Python 3.10+ |
| 可维护 | 模型适配、数据库访问、路由分层，新增模型不改核心逻辑 |
| 视觉 | 不低于基础版；间距、字号、配色统一；无默认浏览器控件裸露 |

## 5. 版本划分

### V1（本次交付，必须完成）
- 账户：注册、登录、退出、个人信息修改、密码修改、bcrypt 存储
- 会话：列表、新建、重命名、删除、切换模型
- 消息：发送、持久化、上下文、失败提示
- 模型：远端 OpenAI 兼容 + 本地 `.pt`（含 LoRA），目录自动扫描
- UI：完整视觉方案 + 空状态 + loading

### V2（有余力再做）
- 流式输出与停止生成
- Markdown / 代码高亮
- Ollama 接入 Qwen 等第三方小模型
- 主题切换、消息重试、导出会话
- 会话搜索

## 6. 验收标准（V1 收口）

1. 新用户可注册并登录，刷新页面保持登录态。
2. 未登录访问 `/chat` 自动跳转登录页。
3. 可新建会话、重命名、删除，操作后数据经刷新仍正确。
4. 在同一个会话中，先选远端模型提问，再切换本地模型提问，两轮都能得到回复，且界面显示对应模型名。
5. 数据库 `users.password` 字段为哈希值，非明文。
6. 本地模型目录新增一个模型后，点击"刷新模型"即可在选择器中出现。
7. 关闭后端再启动，历史会话与消息完整保留。
8. 断网情况下调用远端模型，界面给出明确失败提示而非一直转圈。
9. 在 1280×720 分辨率下主界面无横向滚动条。

## 7. 待确认事项（开发前必须定稿）

| 编号 | 事项 | 影响 | 建议 |
| --- | --- | --- | --- |
| Q-1 | "密码传输加密"的具体口径 | 影响登录接口实现 | 建议作业答辩时向老师确认：HTTPS 即视为传输加密，或前端 SHA-256 预处理后提交。默认实现：前端 SHA-256 + 后端 bcrypt，两层都做 |
| Q-2 | 本地数据库最终用 MySQL 还是 SQLite | 影响部署 | 方案：SQLAlchemy 抽象，开发用 SQLite，交付前切 MySQL，只改连接串 |
| Q-3 | 默认主题风格 | 影响 UI 工作量 | 建议浅色简洁风，聊天类产品更稳妥 |
| Q-4 | 本地模型的实际参数量与显存占用 | 影响能否与 Ollama 同时运行 | 先实测加载，再决定是否接入第三方本地模型 |
